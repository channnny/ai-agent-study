# Claude Code 실습 로그

## 실습 개요

- 실습 주차: 1주차
- 실습 목적: Claude Code로 로컬 파일 읽기/쓰기 에이전트 흐름 경험
- 원본 파일: `input/sample-admission-raw.md`
- 생성 파일:
  - `output/sample-admission-summary.md`
  - `output/sample-admission-summary.json`

---

## 수행한 작업

1. `CLAUDE.md`의 작업 규칙을 기준으로 출력 형식을 정했습니다.
2. `input/sample-admission-raw.md`의 대학별 전형 데이터를 읽었습니다.
3. 각 전형을 사람이 검수하기 쉬운 줄글 형태로 정리했습니다.
4. 향후 DB 입력을 고려해 JSON 구조화 출력도 함께 작성했습니다.
5. 원본만으로 확정할 수 없는 항목은 `확인 필요`로 분리했습니다.

---

## 생성 결과 요약

### Markdown 결과

- 대학/학과별 한 문단 요약 생성
- 확인 필요 사항 테이블 생성
- 사람 검수 체크리스트 생성
- 다음 주차로 넘길 질문 정리

### JSON 결과

- `university`
- `department`
- `admissionType`
- `quota`
- `selectionMethod`
- `minimumRequirement`
- `documents`
- `notes`
- `summary`
- `needsReview`

위 필드로 구조화했습니다.

---

## 사람이 확인해야 할 점

- `없음`과 `확인 불가`가 혼동되지 않았는지 확인해야 합니다.
- 학교장 추천 세부 조건처럼 원본에 없는 내용은 추가하지 않았는지 확인해야 합니다.
- 논술고사 일정처럼 원본에서 확인 필요로 제시된 항목이 누락되지 않았는지 확인해야 합니다.
- JSON의 `quota`가 숫자 타입으로 저장되는지 확인해야 합니다.
- `documents` 값이 DB 스키마와 맞는 표현인지 확인해야 합니다.

---

## 배운 점

- 단발 LLM 호출은 텍스트 답변으로 끝나지만, 에이전트 방식은 파일을 읽고 결과 파일을 생성하며 로그까지 남길 수 있습니다.
- 에이전트에게 작업 규칙을 명확히 주면 출력 형식의 일관성이 좋아집니다.
- 단, 원본 데이터가 애매할 경우 모델이 자연스럽게 보완하려는 경향이 있을 수 있어 `추측 금지`와 `확인 필요` 규칙이 중요합니다.
- Markdown은 사람이 검수하기 좋고, JSON은 다음 단계인 DB 입력 자동화에 유리합니다.
