# Claude Code 실습 로그

## 실습 개요

- 실습 주차: 1주차
- 실습 일자: 2026-04-29
- 실습 목적: Claude Code로 로컬 파일 읽기/쓰기 에이전트 흐름 경험
- 원본 파일: `input/sample-admission-raw.md`

---

## 수행한 작업

1. `CLAUDE.md`의 작업 규칙과 출력 형식을 확인했습니다.
2. `input/sample-admission-raw.md`에서 A·B·C 3개 대학의 전형 정보를 읽었습니다.
3. 각 학과별 전형을 사람이 검수하기 쉬운 줄글 한 문단으로 정리한 Markdown 결과를 생성했습니다.
4. DB 입력 가능성을 고려해 `university`, `department`, `admissionType`, `quota`, `selectionMethod`, `minimumRequirement`, `documents`, `notes`, `summary`, `needsReview` 필드로 구조화한 JSON 결과를 생성했습니다.
5. 원본에서 미확정으로 표시된 항목과 원본에 없는 부가 정보 요청 가능성이 있는 항목을 `확인 필요 사항`/`needsReview`로 분리했습니다.
6. 본 로그 파일을 갱신했습니다.

---

- 수정: `output/sample-admission-summary.md`
- 수정: `output/sample-admission-summary.json`

## 사람이 확인해야 할 점

- A대학교 소프트웨어학부: 1단계 3배수 선발, 2단계 비율(1단계 70% + 면접 30%)이 정확히 옮겨졌는지 확인.
- B대학교 컴퓨터공학과: 수능최저학력기준의 영역(국어/수학/영어/탐구)과 등급 합 6 이내 표현이 누락되지 않았는지 확인.
- C대학교 인공지능학과: `별도 제출서류 없음`을 `확인 불가`로 잘못 해석하지 않았는지(JSON `documents`에 `["없음"]`으로 표기), 논술 일정·자연계열 출제 `예정`이 `needsReview`에 포함되었는지 확인.
- 원본에 없는 경쟁률, 입결, 합격선, 내신 등급, 모집 시기 등이 추가되지 않았는지 확인.
- Markdown 줄글 요약과 JSON `summary` 내용이 서로 모순되지 않는지 교차 검수.
- JSON `quota` 값이 숫자 타입(35, 20, 12)으로 저장되었는지, `documents`/`selectionMethod`/`needsReview`가 배열 타입으로 저장되었는지 확인.

---

## 배운 점

- 단발 LLM 호출은 텍스트 답변으로 끝나지만, 에이전트 방식은 파일을 읽고 결과 파일을 생성하며 로그까지 남길 수 있습니다.
- `CLAUDE.md`로 작업 규칙·출력 형식을 명시하면 결과의 일관성이 크게 좋아집니다.
- 원본이 애매할 경우 모델이 자연스럽게 보완하려는 경향이 있으므로, `추측 금지`와 `확인 필요` 규칙을 명문화하는 것이 중요합니다.
- Markdown은 사람 검수에, JSON은 다음 단계인 DB 입력 자동화에 각각 유리합니다.
