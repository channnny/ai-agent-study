# 용어집 v1

## 1. LLM 단발 호출

사용자가 한 번 질문하고 모델이 한 번 답변하는 방식입니다.

예시:

```text
이 입학 전형 데이터를 줄글로 요약해줘.
```

특징:

- 빠르게 결과를 얻을 수 있습니다.
- 파일 생성, 검증, 반복 처리, 로그 작성은 별도 작업이 필요합니다.
- 결과가 재현 가능하거나 추적 가능하다고 보장하기 어렵습니다.

---

## 2. AI 에이전트

목표를 받은 뒤, 필요한 정보를 읽고 도구를 사용하며 여러 단계를 거쳐 작업을 수행하는 AI 시스템입니다.

예시:

```text
입력 파일을 읽고, 정제 결과를 Markdown과 JSON으로 만들고, 검수 로그까지 남겨줘.
```

특징:

- 파일 읽기/쓰기, 명령 실행, 외부 도구 호출이 가능합니다.
- 작업을 여러 단계로 나누어 수행합니다.
- 사람이 검수해야 하는 지점을 설계할 수 있습니다.

---

## 3. Claude Code

Anthropic의 에이전틱 코딩 도구입니다. 터미널이나 IDE에서 프로젝트 파일을 읽고, 코드를 수정하고, 명령을 실행하며 개발 작업을 도와줍니다.

이번 스터디에서는 Claude Code를 사용해 다음을 실습합니다.

- 로컬 파일 읽기
- 로컬 파일 생성/수정
- 작업 규칙 적용
- 실습 로그 작성

---

## 4. MCP, Model Context Protocol

AI 애플리케이션이 외부 데이터, 도구, 워크플로우와 연결되기 위한 표준 프로토콜입니다.

예시:

- 파일 시스템 연결
- DB 연결
- Notion/Slack/Jira/Figma 같은 업무 도구 연결
- 검색, 계산, 배치 처리 도구 연결

이번 1주차에서는 MCP를 깊게 구현하지 않고, "에이전트가 도구와 데이터를 연결해 작업한다"는 개념을 이해하는 데 집중합니다.

---

## 5. Tool Use

AI 모델 또는 에이전트가 텍스트 답변만 하는 것이 아니라 외부 도구를 호출하는 행위입니다.

예시:

- 파일 읽기
- 파일 쓰기
- 테스트 실행
- 터미널 명령 실행
- DB 조회
- API 호출

---

## 6. Human-in-the-loop, HITL

AI가 모든 작업을 자동으로 끝내는 것이 아니라, 중요한 지점에서 사람이 검수하거나 승인하는 구조입니다.

이번 프로젝트에서의 예시:

- 원본 데이터 정제 후 사람이 샘플 검수
- DB 입력 전 승인
- 오류 또는 불확실 항목만 사람이 확인
- 최종 운영 전 담당자 UAT 수행

---

## 7. Deterministic Task, 규칙 기반 작업

같은 입력이면 같은 결과가 나와야 하는 작업입니다.

예시:

- 모집인원 숫자 추출
- 전형명 추출
- 제출서류 목록 추출
- 파일명 규칙에 따라 저장

이런 작업은 LLM보다 코드나 후처리 로직으로 처리하는 것이 안정적일 수 있습니다.

---

## 8. Ambiguous Task, 판단 기반 작업

원본이 애매하거나 맥락 판단이 필요한 작업입니다.

예시:

- 여러 문장에 흩어진 전형방법을 사람이 읽기 쉬운 문장으로 재구성
- 예외 조건을 요약
- 실무자가 검수해야 할 위험 요소 분류
- 설명이 부족한 항목을 `확인 필요`로 판단

이런 작업은 LLM이 유용하지만, 평가 기준과 검수 절차가 필요합니다.

---

## 9. Structured Output, 구조화 출력

LLM 결과를 사람이 읽는 문장뿐 아니라 프로그램이 처리할 수 있는 JSON, CSV, DB 필드 형태로 출력하는 방식입니다.

이번 프로젝트에서는 줄글 Markdown과 함께 JSON을 생성해 향후 DB 입력 단계로 이어질 수 있게 합니다.

---

## 10. Evaluation, 평가

AI 출력물이 좋은지 나쁜지 판단하는 기준과 절차입니다.

이번 프로젝트에서 평가할 수 있는 항목:

- 원본 충실도
- 누락 여부
- 추측 여부
- JSON 필드 정확도
- 사람이 검수하기 쉬운 정도
- DB 입력 가능성
