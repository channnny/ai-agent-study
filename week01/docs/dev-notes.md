# 개발자 노트

## 1주차에서 너무 깊게 하지 않아도 되는 것

- 실제 API 연동
- DB 입력
- MCP 서버 직접 구현
- 실제 운영 데이터 처리
- 완전 자동화 파이프라인 구축
- 평가 스크립트 작성

1주차는 개념 정립과 파일 읽기/쓰기 실습이 목표입니다.

---

## 그래도 미리 생각하면 좋은 것

### 1. Markdown과 JSON을 같이 생성할 것인가?

Markdown은 사람이 읽기 좋고, JSON은 코드가 처리하기 좋습니다.  
향후 DB 입력 자동화를 고려하면 JSON 스키마를 일찍 잡아두는 것이 좋습니다.

### 2. LLM이 하면 안 되는 작업은 무엇인가?

예를 들어 모집인원 숫자는 LLM이 자연어로 재작성하기보다 원본에서 정확히 추출되어야 합니다.  
이런 값은 나중에 코드 기반 파서나 검증 로직으로 처리하는 것이 안전할 수 있습니다.

### 3. 사람 검수 지점은 어디인가?

DB 입력 전에는 반드시 사람이 승인해야 할 가능성이 큽니다.  
특히 수능최저, 전형방법, 모집인원은 잘못 입력될 경우 영향이 크므로 검수 게이트가 필요합니다.

## 2주차로 가져갈 개발자 질문

1. 실제 원본 데이터 파일 형식은 무엇인가?
2. 한 파일에 여러 대학/전형이 섞여 있는가?
3. 표 구조가 일정한가, 매년 달라지는가?
4. 사람이 현재 어떤 기준으로 줄글을 작성하는가?
5. DB에 들어가는 필드명과 타입은 무엇인가?
6. 입력 실패/중복 입력/검수 반려 케이스는 어떻게 처리해야 하는가?
