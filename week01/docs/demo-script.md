# 금요일 데모 스크립트

## 3분 데모 버전

### 1. 설치와 환경 설명, 40초

Claude Code를 로컬에 설치했고, 1주차 실습용 폴더를 만들었습니다.

프로젝트 루트에는 `CLAUDE.md`를 두어 에이전트가 따라야 할 작업 규칙을 정의했습니다.  
이번 실습의 목표는 단순히 AI에게 요약 답변을 받는 것이 아니라, 로컬 파일을 읽고 결과 파일을 생성하며 로그까지 남기는 흐름을 확인하는 것입니다.

---

### 2. 실습 흐름 설명, 1분

입력 파일은 `input/sample-admission-raw.md`입니다.  
여기에는 샘플 대학 전형 데이터가 들어 있습니다.

Claude Code에게 다음 작업을 요청했습니다.

1. 입력 파일 읽기
2. `CLAUDE.md` 규칙 적용
3. 사람이 검수하기 쉬운 Markdown 생성
4. DB 입력을 고려한 JSON 생성
5. 작업 로그 작성

생성 결과는 아래 파일에 저장했습니다.

- `output/sample-admission-summary.md`
- `output/sample-admission-summary.json`
- `logs/claude-session-note.md`

---

### 3. 배운 점, 1분

단발 LLM 호출은 답변 생성에서 끝나지만, 에이전트 방식은 파일을 읽고, 규칙을 적용하고, 여러 결과물을 생성하는 흐름까지 이어질 수 있었습니다.

다만 원본 데이터가 애매할 때 모델이 추측할 가능성이 있으므로, `추측 금지`, `확인 필요`, `사람 검수 체크리스트` 같은 규칙이 중요하다는 점을 확인했습니다.

다음 주에는 조교 업무를 더 잘게 쪼개서 어떤 작업은 규칙 기반으로 처리할지, 어떤 작업은 LLM 판단에 맡길지 분류해야 할 것 같습니다.

---

## 1분 요약 버전

Claude Code를 설치하고, 1주차 실습용 폴더에서 파일 읽기/쓰기 에이전트 흐름을 실습했습니다.

입력 파일인 샘플 입결 데이터를 읽게 한 뒤, 사람이 검수하기 쉬운 Markdown 결과와 DB 입력을 고려한 JSON 결과를 생성했습니다. 또한 작업 로그와 검수 체크리스트도 남겼습니다.

이번 실습을 통해 단발 LLM 호출과 에이전트의 차이를 확인했습니다. 단발 호출은 답변에서 끝나지만, 에이전트는 로컬 파일을 읽고, 규칙을 적용하고, 결과 파일을 생성하는 식으로 여러 단계를 수행할 수 있습니다.

다음 주에는 실제 조교 업무를 단계별로 쪼개서, 규칙 기반으로 처리할 부분과 LLM 판단이 필요한 부분을 분류하는 것이 중요해 보입니다.
