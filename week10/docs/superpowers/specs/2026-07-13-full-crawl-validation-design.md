# 전량 크롤 검증 + 시간 대응 — 설계 (W10)

> 목적: 전체 220개 대학 전형정보 재크롤 **전/후** 검증을 확실히 처리해, 배포 후 데이터랩스가
> 문제를 발견해 되돌아오는 **피드백 핑퐁을 우리 쪽 게이트에서 선차단**한다. 동시에 물리적으로
> 긴 크롤 시간을 완주 가능하게 만든다.

## 배경 / 문제
- 지난 핑퐁 3대 원인: **(1) 구조 결함**(빈파일·열깨짐), **(2) 완전성 결함**(누락 대학·과소열거),
  **(3) 정합성 결함**(셀 값 오류·조인 실수).
- (1)은 W10 검증 시트로 이미 처리. 남은 건 (2)(3).
- 크롤 시간: detail fetch ~6.5만 유닛 + Playwright 열거 → 수 시간. 맥 잠자기가 장시간 무인 실행의 적.

## 결정 사항 (사용자 승인)
- **검증 깊이 = B**: 자동(구조+완전성) 리포트 + 정합성 HITL 표본검수.
- **열거 전략 = 하이브리드**: 캐시 재사용 + 의심 캐시만 재열거.
- 사이트 '총 N건' 정량 대조(옵션 C)는 **범위 밖**. (완전성 보증 한계는 아래 명시)

## A. 자동 검증 리포트 — `validate.py` (크롤과 분리, 언제든 재실행)

크롤 산출물(`output/대학별/*.xlsx` + `output/enum/*.json` + `target_universities.csv`)을 읽어
`output/검증_리포트.xlsx` 생성. **크롤을 다시 돌리지 않고도** 재검증 가능.

### 검사 항목

| # | 검사 | 정의 | 판정 | 잡는 핑퐁 |
|---|---|---|---|---|
| A1 | **완전성 L1 (열거→출력)** | 대학별 (성공+기타제외+실패) == 열거 유닛수 | 불일치 = FAIL | 유닛 조용히 증발 |
| A2 | **커버리지** | target 220 코드 전부 `대학별/` 파일 존재 | 누락 = FAIL | 대학 통째 누락 |
| A3 | **구조/스키마** | 각 파일: 시트 2개, 전형일정 46열·전형요소 55열, 3단 헤더, 식별 8열 명칭 일치 | 불일치 = FAIL | 열 깨짐 |
| A4 | **0행 사유분류** | 성공 0행 대학 → 전부기타제외 / 전부실패 / 열거0 분류 (기존 검증 시트 로직) | 전부실패·열거0 = WARN | 빈파일(경동류) |
| A5 | **per-column 진단** | 전형일정 46열 + 전형요소 55열 각각 **채움률(%)·distinct 수** 산출 | 채움률 0% = WARN(항상빈), distinct==1 & 비어있지않음 = INFO(항상동일) | 지난 7건 피드백 직격(영어 과목명 항상빈, 학생부 열 항상빈 등 체계적 오류) |
| A6 | **enum 이상치** | 대학별 열거 유닛수를 나열·정렬 + 재열거된 대학의 (신규 vs 캐시) 델타 | 저건수(<3) 또는 재열거 델타>0 = WARN | 과소열거(연세 40 vs 853류) |

### 완전성 보증의 한계 (정직하게 명시)
- **강한 보증 = A1**: 열거된 모든 유닛이 출력에 계상됨(성공/기타/실패 중 하나). 조용한 누락 0.
- **약한 보증 = A6**: 열거 자체의 완전성은 독립 기준(사이트 총건수)이 범위 밖이라 **정량 보증 불가**.
  대신 (a) 저건수 이상치 플래그, (b) 의심 대학 재열거 델타로 근사. 리포트에 "완전성 = L1 보증 /
  L2 근사"를 명기해 데이터랩스와 기대치를 맞춘다. → 이 정직한 명시 자체가 핑퐁을 줄임.

### 리포트 시트 구성 (`검증_리포트.xlsx`)
1. **종합** — 각 검사 PASS/WARN/FAIL 요약 + 배포 게이트 판정(FAIL 0건이어야 통과)
2. **완전성** — 대학별 열거수/성공/기타/실패/L1일치여부, 커버리지 누락 목록
3. **스키마** — 파일별 열수·헤더 불일치 목록 (정상은 생략)
4. **per-column** — 시트별 열 × (채움률, distinct, 플래그)
5. **enum이상치** — 대학별 열거수 정렬 + 재열거 델타
6. **0행경고** — 기존 검증 시트

## B. 정합성 HITL 표본검수 — `sample_review.py`

랜덤 표본을 원본과 나란히 놓고 사람이 O/X. **배포 전 사인오프 게이트.**

- **표본 N=30 유닛**, 대학·전형 대분류 **stratified**(한 대학·한 전형에 몰리지 않게). 재현 위해 시드 고정.
- 산출: `output/표본검수_시트.xlsx` — 유닛당 한 블록:
  - 상단: 식별(대학/전형/모집단위) + 구조화된 행(전형일정 46 / 전형요소 55 평면값)
  - 하단: **어디가 원본 표 그대로**(`write_blocks` 재사용) — 전형일정및방법/전형요소 캡션별 표
  - 검수 열: `정합성 O/X`, `메모`
- per-column 진단(A5)이 **체계적** 오류를, 표본검수가 **개별** 오류를 커버 → 상호보완.
- 한계: 표본은 spot-check(전수 아님). A5와 병행해 체계적 오류는 전수 진단으로 보완.

## C. 열거 하이브리드 + 시간 대응

### 열거 (하이브리드)
- 기본: `output/enum/<코드>.json` 캐시 재사용(Playwright 생략).
- **재열거 대상(의심 캐시)**:
  1. enum 파일 없음, 또는 유닛수 == 0
  2. 유닛수 < 3 (실 대학은 통상 ≥ 수 건)
  3. 크롤 결과 성공 0행인 대학 (열거실패인지 진짜 기타/무모집인지 재확인)
- 재열거 후 (신규 vs 캐시) 델타를 A6에 기록. 신규>캐시면 캐시가 과소였던 것 → 신규 채택.
- 경동대[본교](5건 전부 기타)는 재열거해도 5건 확인 → "진짜 기타"로 검증됨(핑퐁 선차단).

### 시간 / 완주
- `caffeinate -i` 로 맥 잠자기 방지(장시간 무인 실행).
- 백그라운드 실행 + **resume**: `run_all`은 `대학별/<대학명>.xlsx` 존재 시 스킵 → 중단돼도 이어서.
- 진행 로그(타임스탬프, [i/220], 누적/경과) 기존 유지.
- 워커 6 유지(net.py 서킷브레이커·지연과 균형; 무리한 증가는 차단/밴 리스크).
- 예상: enum 대부분 캐시히트 → detail fetch 지배, ~3–4h. 중단 시 이어받기.

## 실행 흐름 (배포 게이트)
```
1. 의심 캐시만 재열거                         (빠름)
2. caffeinate + 백그라운드 structured.py --all  (resume, 진행로그)
3. validate.py         → 검증_리포트.xlsx      (A: FAIL 0 게이트)
4. sample_review.py    → 표본검수_시트.xlsx     (B: 팀 사인오프 게이트)
5. (A 통과 && B 사인오프) 후에만 데이터랩스 배포
```

## 컴포넌트 경계 (각 단위 = 단일 목적)
- `validate.py` — 산출물 읽기 전용 검사 → `검증_리포트.xlsx`. 크롤·네트워크 의존 없음.
- `sample_review.py` — 표본 선정 + 원본 fetch(`write_blocks`) + 검수 시트. 
- `structured.py` (기존) — 크롤·구조화·리포트. 변경 최소(재열거 트리거 옵션만 추가 검토).
- 각 스크립트 독립 실행·재실행 가능. 검증은 크롤 없이도 반복 가능.

## 테스트
- `validate.py`: 인위적 결함 픽스처(열 누락 파일, 유닛수 불일치, 항상빈 열)로 각 검사가 FAIL/WARN 잡는지 단위 테스트.
- 7개 테스트 대학 산출물로 e2e 스모크(검증 리포트 생성 + 경동 0행 WARN 확인).

## 비목표 (YAGNI)
- 사이트 '총 N건' 실시간 대조(옵션 C) — 범위 밖.
- 표본 전수 검수 — spot-check + per-column 전수 진단으로 갈음.
- 워커 수 동적 튜닝·분산 — 현행 6 고정.
