# 표기 정규화 사전

> rule-mapper 스킬이 참조하는 매핑 사전. adiga 페이지의 다양한 표기를 골든셋 양식과 일치시킨다.

---

## 1. 반영교과 표기

| adiga 표기 | 골든셋 표기 |
|---|---|
| 전 과목 | 전교과 |
| 전과목 | 전교과 |
| 전체 | 전교과 |
| 전체 과목 | 전교과 |
| 국,수,영,사 | 국,수,영,사 |
| 국 수 영 사 | 국,수,영,사 |
| 국·수·영·사 | 국,수,영,사 |

규약: 쉼표 구분, 공백 제거, 중간점(·) → 쉼표 변환.

---

## 2. 학생부등급 기준 컬럼

| adiga 헤더 텍스트 | 골든셋 값 |
|---|---|
| 최종등록자 | 최종등록자 |
| 최종등록자 기준 | 최종등록자 |
| 합격자 평균 | 합격자 |

기본값: "최종등록자" (대부분 대학이 이 기준으로 공개)

---

## 3. 빈 셀 / NULL 표기

다음은 모두 NULL로 처리:
- `-`
- `–` (en dash)
- 빈 문자열
- ` ` (공백만)
- `N/A`
- `해당없음`
- `미공개`

---

## 4. 숫자 정규화

| 패턴 | 처리 |
|---|---|
| `1,234` (천 단위 구분자) | `1234` |
| `12.5%` | `12.5` (퍼센트 기호 제거) |
| `12점` | `12` |
| `3배수` | `3` (배수는 정수만) |
| `3~5배수` | `3~5` (string 유지) |
| `약 25명` | `25` |

---

## 5. Boolean 표기

| 패턴 | 값 |
|---|---|
| 있음 / 적용 / ○ / Y / O / TRUE | True |
| 없음 / 미적용 / × / N / X / FALSE | False |
| 모집단위별 / 일부 | NULL (별도 모집단위별 처리) |

---

## 6. 전형구분 대분류 매핑

원본 전형명에 다음 키워드 포함 시 대분류 자동 할당:

| 키워드 | 대분류 |
|---|---|
| 학생부교과, 교과전형 | 학생부위주(교과) |
| 학생부종합, 종합전형, 활동우수, 계열적합, 가천바람개비 | 학생부위주(종합) |
| 논술 | 논술위주 |
| 실기, 실적 | 실기/실적위주 |
| 수능, 정시 | 수능위주 |
| 위 어디에도 안 잡힘 | 기타 |

여러 키워드 매치 시: 가장 먼저 매치된 대분류 사용.

---

## 7. 면접유형 매핑

| 키워드 | 면접유형 |
|---|---|
| 제시문, 논리적 사고 | 제시문_논리사고 |
| 인적성, 인·적성 | 인적성_면접 |
| 단계별, 1단계, 2단계 (면접이 단계별) | 단계별심층_2회 |
| 실기, 실연, 작품 심사 | 실기포함 |
| 서류진위, 서류확인, 서류기반 | 서류기반_확인 |
| 없음, 미실시 | 없음 |

---

## 8. 평가표기방식 자동 판정

평가요소 비중 값을 보고 자동 판정:
- 비율 합이 100에 근접 (90~110) → `비율백분율`
- 'A+', 'B0', 'C' 같은 등급 토큰이 6~8개 등장 → `등급제_7단계` 또는 `등급제_8단계` (F 포함 여부로 구분)
- '400', '300' 같은 큰 정수가 총합 1000 근처 → `점수제`
- 비중 표기 자체가 없음 → `정성종합`
- 단계별로 표기방식 다름 → `혼합`

---

## 9. 캠퍼스 분리 패턴

모집단위명에 다음 패턴이 있으면 별도 컬럼 `캠퍼스`로 분리:

| 패턴 | 캠퍼스 |
|---|---|
| `(글로벌)`, `글로벌캠퍼스` | 글로벌 |
| `(메디컬)`, `메디컬캠퍼스` | 메디컬 |
| `(상주)`, `상주캠퍼스` | 상주 |
| `(양산)`, `양산캠퍼스` | 양산 |
| `(밀양)`, `밀양캠퍼스` | 밀양 |
| `(아미)`, `아미캠퍼스` | 아미 |
| `(세종)` | 세종 |
| `(미래)` | 미래 |

기본값: `본교`

---

## 10. 향후 확장 규약

이 사전은 운영 중 발견되는 새 표기를 추가하며 성장한다. T4c (`schema-proposer`)가 발견한 패턴 중 정형화 가능한 것은 이 파일에 추가한다.

새 항목 추가 시:
- 단순 표기 차이 → 표 한 줄 추가
- 복잡한 규칙 → 별도 섹션 추가 + 알고리즘 명세

변경 이력은 git log로 관리.
