## 🔧 Input(대학코드·년도)은 어디로? — 자주 나오는 질문

- 대학코드(`unv_cd`)·년도(`search_syr`)는 **크롤링 단계(W03)의 입력**이었다.
  - 파일: `week03/input/target_universities.csv` (헤더 `unv_cd, search_syr, univ_name, memo`)
  - `crawl_adiga.py`가 이를 읽어 어디가 URL의 `searchSyr` 파라미터로 사용 → 전형 결과 추출
- **W06은 크롤링을 다시 하지 않는다.** 이미 크롤된 산출물(`week05/vendor/...`)을 읽어 **통합·평가만** 하는 단계라 그 입력이 직접 안 보인다.
  - 대학코드는 vendor 폴더·파일명(`{unvCd}_...`)에 이미 반영됨
  - 년도는 골든셋(2025학년도)으로 고정
- **년도 매핑(어디가)**: `searchSyr=2026`→2025학년도(수집·골든), `searchSyr=2027`→**2026학년도(최신)**.
- **→ 최신(2026학년도) 실험은 바로 이 입력을 다시 쓰는 작업**: 입력 csv가 이미 `search_syr=2027`로 설정돼 있어 `crawl_adiga.py` 재실행만 하면 최신 결과 수집.

## 🔬 2026 vs 2027 크롤링 차이점 (실측)
> 최신(2027) 크롤 중 발견: 어디가가 **신규 연도 전형결과를 정적→동적 로딩으로 변경**. 기존 requests 크롤러가 목을 먹은 원인. `crawl_adiga.py` 패치로 대응 완료.

| 구분 | searchSyr=2026 (2025학년도 결과) | searchSyr=2027 (2026학년도 결과) |
|---|---|---|
| **표 로딩** | 정적 HTML (inline table) | **동적 AJAX** (`criteriaAndResultItemNewAjax.do`) |
| 버튼 마크업 | 제목 `span.qType`, 번호 있음 | `span.h4`, 번호 없음 |
| 표 헤더 | 인라인 다단헤더 | `<thead>`(3행)+`<tbody>` 분리 |
| 컬럼 스키마 | 모집단위·모집인원·경쟁률·**충원합격순위**·등급컷·반영교과 | +**구분** / 충원합격순위→**충원인원** / 학생부환산점수(50%/70%)·환산등급 |

**어디가 연도 규칙**: `searchSyr=N` = N학년도 전형계획 + (N-1)학년도 입결.

**패치(`week03/crawl_adiga.py`)**: ①'전형 결과' 검출을 버튼 텍스트 기반(클래스 의존 제거) ②정적 표 비면 AJAX fallback ③`<thead>` 행수로 헤더 정확 분리 ④탭 없는 대학 IndexError 가드.

> ⚠️ 컬럼 스키마가 달라져 W05 평가 어댑터(`yuchan.py`)는 2027 스키마 매핑 보강 필요(충원인원·구분 등) → 통합 평가 전 후속.
